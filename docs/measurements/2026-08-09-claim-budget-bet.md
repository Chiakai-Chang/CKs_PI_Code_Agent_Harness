# 2026-08-09 CLAIM 額度實驗:先下注,再量

**寫於任何一次 run 之前。** 這份文件的存在是為了讓事後的我沒有空間編理由。

## 假設

CLAIM 的退場額度從 **4 輪加到 8 輪**,可以讓「認領前不搜尋」更可靠,
**而且**因為階段轉換通知已經存在(2/2 送達),4b 那個「拒絕累積 → 模型放棄整個能力」
的副作用不會重演。

## 我的下注(先寫,後量)

| 指標 | 我賭 | 理由 |
|---|---|---|
| 認領前成功搜尋 = 0 的 run 數 | **2/2** | 8 輪足以撐過模型的初期慣性 |
| 認領後成功搜尋 | **兩次都 > 0** | 通知已實測送達,應能拆掉 4b 的副作用 |
| 走到 `REVIEW` | 2/2 | 乾淨重測已經 2/2 |

**魔鬼代言人的反面下注:第二項會出事。** 8 輪意味著模型可能吃到 40 次拒絕
(一輪 5 個並行呼叫),而 4b 的失效點大約就在 20 次。**如果我錯,會錯在這裡。**

## 判定規則(先定義,不事後解釋)

| 結果 | 判定 |
|---|---|
| 認領前 0/2 **且** 認領後兩次皆 > 0 | **採用 8 輪** |
| 認領前變好,**但任一次認領後 = 0** | **拒絕** —— 那是用產出品質換流程,4b 已經量過那個代價 |
| 認領前仍有 run 大量搜尋 | **拒絕** —— 門檻不是槓桿,要找別的機制 |
| 2/2 皆好但任一次沒到 `REVIEW` | **不採用**,先查為什麼倒退 |

**n=2 只能否證,不能證成。** 若結果支持 8 輪,結論寫成「未被否證」,
並註明需要更多樣本 —— 不寫成「8 輪有效」。

## 結果:**沒有資料。實驗作廢,判定規則不適用。**

兩次 run 都是 `0 個工具呼叫、0 個 assistant 輪次、session 檔為空`,
在「600 秒無成長」後被中止。**那不是模型行為,是沒有跑起來。**

### 排除過程

| 檢查 | 結果 |
|---|---|
| 模型伺服器 | `/health` ok;16 tokens / 3 秒 —— **正常** |
| 孤兒行程 | 0 |
| `pi --print` 在純 temp 目錄 | **正常回應** |
| 安裝版 vs repo | 一致 |
| 門檻改回 4 後在 C.A.S.E. fixture 重試 150 秒 | **仍然無輸出** |

最後一項讓我一度認定「門檻不是原因,是別的東西壞了」。

**而它其實是我自己的錯誤,今天第三次:拿逾時當結論。**

`n_slots: 1`、`n_ctx: 262144`,而 C.A.S.E. 專案的系統提示很大 ——
光是 prompt 處理就可能超過 150 秒。成功那兩次 run 各花了 20–40 分鐘。
**150 秒證明的是我的耐心,不是它的狀態。**

同理,`--quiet 600` 是用「已經在跑的 run」的訊息間隔算出來的(p95 190s、max 237s),
**但那個分布不含「第一次回應之前」的 prompt 處理時間** ——
session 檔在第一次回應之前不會成長,所以 600 秒的靜默門檻對**開場**可能仍然太短。

### 這次量測的真正缺陷

**逾時參數是用錯的分布算的。** 我量的是 run 內部的間隔,而致命的是**啟動到第一筆記錄**的時間,
那是另一個分布,我從來沒量過。

### 下一步(不是重跑實驗)
