## 追加:那兩次「安靜 180 秒」有第二個原因,而且是我造成的

**擁有者先看出來的:模型還在跑,而我這邊什麼都沒有。**

`pi` 在 Windows 解析成 `pi.CMD`,所以啟動走 shell,而 `proc.terminate()` 只殺得到
`cmd.exe` 外殼 —— 底下的 `node.exe` 活了下來,**繼續對本機模型伺服器產生請求**。

實際找到兩個孤兒(8/8 23:35 與 23:47 建立),就是我「中止」的那兩次 run。
它們整夜佔著伺服器的 slot,**而我後續的量測是在跟它們搶**。

> **所謂「安靜 180 秒」,有多少是模型慢、有多少是被孤兒排擠,我分不出來。**
> 那兩次 run 的數字現在只能標為「不可用」,不是「模型沒認領」。

這條疤 repo 裡本來就有(async-exec:Windows 的 `spawn()` 回傳的是啟動器,
**要驗的是殺得掉,不是 pid 相等**)。我知道,而寫這支腳本時沒有套用。

### 修法與證明

* `stop_tree()` 用 `taskkill /T /F` 走整棵樹;測試**實際起一個 shell 子行程、殺掉、驗屍體**。
* 量測前先查孤兒,**有孤兒就拒絕開跑** —— 旁邊有第二個 client 的數字不是量測。
* **第一版的孤兒檢查用 `wmic`,而這台機器根本沒有 `wmic`** ——
  那是一個**永遠回傳空清單、不可能失敗**的檢查,正是我同一天建 `check-guard-mutations`
  要抓的類別。改用 PowerShell CIM,並**起一個真的 `pi --print` 證明它會回非空**
  (抓到 pid 11192),清掉後回空。
