# Round 3:共同盲點檢測 —— 我們是不是太同意了?

**日期**: 2026-08-06
**問題等級**: L2
**協定要求**: 單模型自我參照的緩解輪次

---

**🎭 老魔:**

先問協定要求的那一題:**我們是不是太同意了?**

是。從 Round 2 中段開始,所有人都在往「切分門」靠。沒有人再質疑切分門本身。我來質疑。

**質疑一:第一個搜尋根本不是正確的攔截點。**

你們一直假設要擋「第一個廣義工具呼叫」。但看真實 session 的形狀:

```
turn 1: 搜尋 ~13 次 → 給結論
turn 2: 搜尋 ~13 次 → 給結論(翻轉)
turn 3: 搜尋 ~12 次 → 給結論(再翻轉)
```

**每一輪都是完整的「搜尋→結論」。** 問題不是它沒在第一次搜尋前規劃 —— 是它**在每一輪結束時把整件事收掉了**。

擋第一個搜尋,它會寫個 queue,然後**照樣一輪把三項全做完**。你只是多得到一個檔案。

**🎭 Vera:**

⋯⋯我得承認這跟實測吻合。三個探針 run 都寫了 `task_plan.md`,而且都是**同一輪**寫完 plan、做完全部、給結論。plan 檔存在,一輪做完照舊。

**寫 plan 這個行為已經發生了,而且沒有改變任何事。**

**🎭 老魔:**

謝謝。所以「放行條件 = 有 plan 檔」(原選項 A)在實測上**已經被否證了** —— 那個條件早就被滿足,行為沒變。

**質疑二:你們要擋的東西,擋不到。**

真正該擋的是「這一輪要收掉整件事」的那個時刻。那個時刻在哪?在模型**準備輸出最終答案**的時候。

而 `turn_end` 沒有回傳型別 —— 這件事這個 repo 的記憶裡寫得很清楚。**沒有「即將作答」的事件。**

所以你們想擋的那一刻,Pi 沒有給你槓桿。

**🎭 老陳:**

⋯⋯這是對的。我確認一次:`on(event: "turn_end", ...)` 宣告的 result type 是空的。`before_agent_start` 可以改 systemPrompt,`tool_call` 可以擋,`tool_result` 可以附加內容。就這三個。

**沒有一個發生在「模型決定收尾」的時刻。**

**🎭 阿德:**

那我提一個歪招,但可能是唯一的路。

既然擋不到「作答」,那就**讓作答需要通過一個工具**。註冊一個工具 —— 比方 `queue_advance` —— 然後在 systemPrompt 裡規定:每完成一項要呼叫它才能進下一項。它不是攔截,是**把迴圈的節拍變成一個必須呼叫的東西**。

**🎭 老魔:**

那就回到老問題:寫在 systemPrompt 的規定會被忽略。這一輪剛實測完 —— `research-task-routing` 三個 run 都讀了,裡面的 Source 欄三次都被跳過。

**🎭 CK:**

等等,但這兩件事不一樣。

「請附來源」是一句**要求品質**的話。「呼叫 `queue_advance` 才能進下一項」是一個**工具存在**。模型看得到工具列表,工具是它習慣用的東西。這不是同一種指令。

**🎭 Dr. 林:**

CK 這個區分有文獻支撐。Routine(arXiv 2507.14447)把 Qwen3-14B 的多步工具呼叫從 32.6% 拉到 83.3%,做法正是**把流程變成可執行的腳本**而不是叫模型自己選。工具比散文更接近腳本。

**🎭 老魔:**

我接受這條有機會,但我要把話說死:**這是假設,不是結論。** 這個 repo 有一條血淋淋的教訓叫「未開火的守衛 = 未驗證」。`queue_advance` 會不會被呼叫,只有實測知道,而且只有 CK 的互動 session 測得到。

**質疑三 —— 最後一個,也是最大的:你們在替一個一次性的偏移蓋永久建設。**

真實 session 只有一個。n=1。所有這些設計的證據基礎是**一次**觀察。

**🎭 Vera:**

我要為 n=1 辯護一次。那不是隨機一次 —— 那是 CK 用真實需求跑的真實 session,而且他的抱怨與數據完全吻合(0 write、0 read、三次翻轉)。這叫**存在性證據**:證明這個失效**會**發生,不需要 n=30。

但老魔的警告換個講法是對的:**我們不知道它多常發生。** 所以設計必須是「發生時接得住」,不是「每次都改變流程」。

**🎭 小周:**

那對我來說最好 —— 平常感覺不到,出事才出現。

## 本輪新發現

1. **選項 A 早就被滿足過,而且沒用。** 三個探針 run 都寫了 `task_plan.md`,都還是一輪做完。這不是預測,是紀錄。
2. **Pi 沒有「即將作答」事件** → 想擋「一輪收掉整件事」在架構上擋不到。
3. **唯一可能的槓桿是「把節拍變成工具」** —— 工具是模型會用的東西,散文不是。有 Routine 的證據,但在本機未驗證。
4. **n=1 是存在性證據,不是頻率證據** → 設計必須預設安靜。

## 結論

前兩輪爭論的兩個選項(A 有 plan 檔 / B 載入技能)**雙雙出局**:一個被實測否證,一個違反 CK 的原則。
