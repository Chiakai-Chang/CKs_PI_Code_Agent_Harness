## R16.4 — 老秦的那一刀

**🎭 老秦:** 我一直在等。`universal-tag-transformer` 第三則解析出來的指令是:

```
git add README.md docs/
git commit -m "整理專案結構，新增 README.md 與 docs 指南"
commit fe56ec6
```

`commit fe56ec6` 是 git 的**輸出回顯**,不是指令。解析器把它撈進參數,
然後用「🔥【指令】：請你在此輪對話中【立即且只能】呼叫原生工具 'bash',傳入上述參數!」
命令模型照送。

**把這條路徑寫完整:** 模型的文字 → 解析器 → 一則帶著「立即且只能」的命令 → 模型照送 bash。
而模型的文字裡可以有**它剛剛從網頁讀進來的東西**。
這個 session 開了 12 個網頁。
**一個網頁上的 ```bash 區塊,只要被模型複述,就有一條通往 bash 的路。**

**🎭 老譚:** 這次沒有發生。發生的是把 git 的回顯當指令。

**🎭 老秦:** 「這次沒發生」不是控制措施。而且這條路徑上**沒有任何一個環節在問來源**。
解析器看到的是一段文字,它不知道那段文字是模型想的、還是模型抄的。

**🎭 老魔:** 我幫老秦補強,也幫他設界。這條要立成任務,但**不要立成資安專案**。
這個 repo 有過「把導航問題當成資安問題」的一整輪
([Round 13](2026-08-10_round13_把導航問題當成資安問題.md)),結論是別過度武裝。
**最小的正確動作:解析器只接受它能證明是完整程式碼區塊的內容,
並且對它解析出來的東西做一次形狀檢查**(一行 `commit <sha>` 不是任何工具的合法參數)。

# SWOT

## Strengths
- **根因已經定位到可驗證的層級**:template 的原文、上游 issue 編號、24 次出現位置,三者對得上
- 換模型清單**早就寫對了**,只是沒有被執行 —— 不需要重新思考該檢查什麼
- `citation gate` 在這個 session 裡**正常工作**(拒絕一份 0 網址、已開 5 頁的報告,並列出已開頁面清單),
  證明「顯示你看到的」那條設計是對的
- `verify-bridges.py` 回報 `13 bridges checked, 0 failure(s)` —— **這次不是安裝漂移**,範圍乾淨
- 缺陷一的修法已用實驗證實:手動呼叫 `merge_into_catalog` 得到 `lost []` / `hello-reflect present: True`

## Weaknesses
- **換模型沒有任何自動守門員**,而換 bridge / 設定 / 提示都有
- 技能可達性有**三條互相獨立的註冊路徑**,任何只看一條的判斷都會錯(本次量測自己先錯過一次)
- `restore.py` 的 catalog 寫入與本地折入之間隔著一個 `--config-only` early return
- 偵測器的正則寫死了沒有命名空間前綴的形式
- 解析器把模型文字當指令,而文字可以來自網頁

## Opportunities
- 這次的 20 個髒檔案是一個**乾淨的驗收樣本**:修好之後可以直接重跑同一份 grep 驗證
- `skill-conflict-report.json` 已經是「每個 session 落一份報告」的成熟模式,可以直接套給服務層檢查
- `tests/test_skill_names_resolve.py` 已經在守「叫得出的名字必須註冊得到」,只差把 catalog 與 advisory 文字納入
- 擁有者手上已有 `tests/fixtures/session-fake-tool-call-loop.jsonl`,解析器修法的 fixture 有現成來源

## Threats
- **默默清掉殘留標籤會把根因藏起來**,重演 citation gate 的規避形狀
- 對模型說明服務層問題會浪費輪次並可能改變它的下一步(GateGuard 已示範)
- 動 `external/ecc/` 會在上游更新時撕裂
- 批次崩壞 n=1,而這個 repo 的噪音底線是 sd 26.91 —— 任何單次前後比較都讀不出效果
- 一次修六條會讓效果全部混在一起,重演「七個 A/B 零結論」

## 這一輪最重要的六句

1. **模板換了,而清單沒有跑。** 缺陷不在清單的內容,在它是一份要用眼睛讀的文件 ——
   這個 repo 已經證明過,靠記得維持的東西一個月內會變成沒人讀的範本。
2. **一則訊息的第一個問題是「聽眾是誰」,不是「內容對不對」。**
   GateGuard 的文字是對的,送錯對象就變成 28 次無用呼叫;
   `📝 偵測到新學習點` 的文字送給了看螢幕的人,而它想推動的動作只有模型能做。
3. **技能可達性有三層失敗,不能混為一談** —— 載不到 / 看得到但不知何時用 / 知道卻沒人點名。
   Round 15 修的是第三層,這次發現有 14 個技能卡在第一層。
4. **量測儀器先修。** 上面所有排序爭執用的數字都由 `mine-session.py` 讀出,
   而它把別人的訊息算成了 loop guard 的三次拒絕。
5. **守衛在響,而沒有人聽。** 佇列排完才跑的 `unittest discover` 是
   `1454 tests, FAILED (failures=2)` —— 兩個失敗正是我們剛排成 T-A16 的那個缺陷,
   而且是 **18 個技能不是 14 個**,其中 `thinking-frameworks` **被 CLAUDE.md 的方法論路由指名**。
   「先查既有再動手」這條規矩需要一個自體版本:**動手設計守衛之前,先跑自己的測試套件。**
6. **一個有效的補救,比沒有補救更會藏住成因。**(動手 T-A16 時才學到的)
   那條檢查自 2026-08-04 就在紅,而它印的補救「重跑 restore」**真的有效**。
   紅了就重跑、綠了就過去,十天沒有人問它為什麼一直回來。
   根因是 `--config-only` 的 early return 落在本地名單折入 catalog 之前,
   兩道指令就分岔得出來(120 / 102)。
   **所以防迴歸測試斷言的對象是決定它的那個函式,不是磁碟上的檔案** ——
   磁碟狀態會被下一次 restore 修好,而那正是這個缺陷藏了十天的方式。
