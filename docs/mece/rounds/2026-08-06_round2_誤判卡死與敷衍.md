**🎭 老陳:**

**🎭 小吳:**

**🎭 Vera:**

還有一個我必須說,而且很不受歡迎:**任何互動路徑,`measure-triggers.py` 永遠測不到。** `pi --print` 是單輪、`hasUI` 為 false。

我們這輪剛學到的教訓是「未開火的守衛 = 未驗證」—— 深度閘和產出閘測試全綠、破壞三次全紅、安裝副本一致,實測 0 次開火。**如果我們再蓋一個只在互動下存在的東西,它會是永久未驗證。**

## 本輪新發現

1. **真正的失效模式不是誤擋,是敷衍**。實測有證:引用閘讓編造從 0 變 4;長度下限被小塊寫入繞過。**放行條件必須難以敷衍。**
2. **「有沒有真的填」是可判定的**,雖然「填得好不好」不是。非空、項目數、項目互異 —— 都是純函式。
3. **一律強制會踩 Learning When to Plan 的坑** —— 簡單問題不該付成本。
4. **小周維度**:這是開源專案,擋阻訊息要讓不知情的人看得懂,而且要說得出怎麼關掉。
5. **互動路徑永久未驗證** —— 這是反對對話框方案的最強論據。

## 結論

放行條件的設計準則從「要求什麼」改成「**要求一個難以敷衍的東西**」。
