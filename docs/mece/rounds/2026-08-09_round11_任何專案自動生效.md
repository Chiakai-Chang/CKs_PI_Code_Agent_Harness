## 第一輪:先把選項空間攤開,不要只有 A 和 B

**🎭 老方:** CK 指定走 A,但 A 不是一個設計,是一個方向。**觸發來源**這一維至少有五個互斥選項:

| # | 觸發來源 | 何時知道 | 代價 |
|---|---|---|---|
| T1 | **檔案系統狀態**(現況:有 `02_Task_Queue/`) | session 開始 | 需要 bootstrap → 就是被否決的現況 |
| T2 | **使用者提示的形狀**(`before_agent_start.prompt`) | **第零輪** | 分類器,有偽陽率 |
| T3 | **工具呼叫的模式**(連續 N 次搜尋 / 寫了 M 個檔) | 第 3–5 輪 | 太晚 —— 已經開始搜了 |
| T4 | **模型自陳**(問它「這是研究型任務嗎」) | 第零輪 | 實測 0/3:模型不會主動提議 |
| T5 | **使用者明確標記**(`/case-init`、`.pi-harness.json`) | 使用者決定 | 就是 B,CK 已否決 |

**T2 是唯一「夠早又不需要使用者做事」的。** T3 太晚是實測結論:
4b 那次模型**第一輪就發出五個並行搜尋**。

**🎭 老譚:** 那 T2 就是一個分類器,而分類器必須先講偽陽率。
`019fe60f` 的提示長這樣:

> 「請分析了解最近比較重要的社會事件,找出是否有關連,循線找出脈絡… 請 MECE 的分析哪些利害關係人會受影響… 並復盤這些建議是否合適」

這是明確的多階段研究。但**「幫我把這個變數改名」也會進來**。
**偽陽性的代價是什麼?** 在一個改名任務上要求「先寫 planning.md」——
那是 CK 最初抱怨的反面:harness 擋路。

**🎭 老魔:** 我下注:**如果偽陽率不先量,這東西兩天內就會被關掉。**
CK 已經有一個關著的旗標了(`enableCaseAdvancer`),再加一個會被關掉的機制,
就是把「有反應沒有結果」升級成「有反應而且惹人厭」。

**🎭 秦姐:** 補一個協定層的事實:C.A.S.E. 的階段是**任務包的狀態**,不是 session 的狀態。
在沒有任務包的專案裡,「認領」沒有對象。
**所以 A 不能是「把現有機制搬過去」,必須是「一個不需要任務包的輕量對應物」。**

## 第二輪:輕量版該強制什麼(這是真正的分歧)

**🎭 老韓:** 現有三個機制,拆開看在無佇列情境下各自還剩什麼:

| 機制 | 依賴任務包? | 無佇列時可行的對應物 |
|---|---|---|
| 階段閘(先認領) | **是** —— 認領的是任務 | 「先寫下你要做什麼」= 一個計畫,不是一個狀態檔 |
| 推進器(下一步) | **是** —— 讀狀態表 | 無對應物。沒有狀態機就沒有下一步 |
| Path A 驗收 | 部分 —— 需要 DoD | **有對應物**:回報你做了什麼、給選項 |

**所以輕量版最多只有兩件事:開工前先有計畫、結束時回報並給選項。**

**🎭 阿凱:** 而這兩件事**不需要新的協定**。它們就是 `for_humans.md` 步驟三的兩端。

**🎭 小晴:** 那政策要寫在哪?若「任何專案自動生效」,
**這就是全域預設,而全域預設必須能被單一專案關掉。**
`.pi-harness.json` 的分域已經做好了 —— **方向要反過來:預設開,專案可關。**

**🎭 小葉:** 我要擋一件事。**不准在使用者的專案裡自動建檔。**
`019fe60f` 的專案有 16 個編號檔案,那是 CK 自己的資產。
harness 在裡面自動寫 `planning.md` 或 `02_Task_Queue/` 就是污染。

**🎭 老陳(查了安裝版型別):** 這一點有解,而且不必妥協:

```
appendEntry(customType, data)  // "Append a custom entry to the session
                               //  for state persistence (not sent to LLM)"
```

**session 級的持久狀態,不落在專案目錄裡。** 輕量版的狀態可以完全活在 session 裡。

**🎭 阿海:** 那我問 SRE 的問題:**這東西在別人機器上壞掉時會怎樣?**
若分類器誤判、閘擋住第一個工具呼叫,而使用者只是想改個變數名 ——
他會以為 Pi 壞了。**必須 fail open,而且退場要比 C.A.S.E. 版更快。**

## 第三輪:外部依據,以及它推翻了什麼

**🎭 Vera:** 我去查了 Anthropic 的 building-effective-agents,逐字:

> 「you should consider adding complexity **only** when it demonstrably improves outcomes」
> 「optimizing single LLM calls with retrieval and in-context examples is usually enough」
> workflows 適用於「predictable, well-defined tasks that benefit from decomposition」;
> agents 只用於「open-ended problems where it's difficult or impossible to predict the required number of steps」

**這推翻了「一律套用」。** 官方指引明講:**依任務類別 routing,而不是對所有輸入加同一層編排。**

**🎭 老譚:** 那就把設計定死成 routing:**分類器只在「高信心是多階段研究」時啟動輕量流程,
其餘一律不動。** 而且判定門檻要**偏保守** —— 偽陰(該啟動沒啟動)的代價是「回到現狀」,
偽陽的代價是「惹惱使用者並被關掉」。**兩者不對稱,門檻就該不對稱。**

**🎭 老魔:** 我改下注:**如果門檻夠保守,它會變成什麼都不做。**
`019fe60f` 那種提示會命中,但 CK 平常八成的提示不會。
**那我們得到的是一個一年響三次的機制。**

**🎭 CK(擁有者):** 補一句事實 —— 我抱怨的就是那種 session。
一年響三次但每次都對,好過每次都響而我把它關掉。

**🎭 老趙(稽核):** 那就必須**記錄每一次分類結果**,包含沒啟動的。
否則「一年響三次」和「壞掉了」在紀錄上長得一樣 ——
這正是本週三輪量測被環境弄廢時的同一個問題。

## 第四輪:收斂

**共識(全體):**

1. **觸發來源 = T2**(`before_agent_start.prompt`),因為它是唯一夠早又不需要使用者做事的。
2. **強制的內容 = 兩件事,不是三件**:開工前先有計畫、結束時回報並給選項。
   **推進器不進輕量版** —— 沒有狀態機就沒有下一步,硬做會變成猜。
3. **狀態用 `appendEntry` 存在 session,不寫使用者專案。**(小葉的紅線,老陳給的解)
4. **分類是 routing 不是攔截**:高信心才啟動,其餘完全不動(Anthropic 指引)。
5. **門檻不對稱**:寧可漏,不可擾。
6. **每一次分類都記錄**,含未啟動 —— 否則分不出「很少響」與「壞了」。
7. **專案可關**:`.pi-harness.json` 反向使用(預設開、單一專案可關)。
8. **fail open + 更快的退場**:別人的專案不是我們的實驗室。

**未解、且明列為未解:**

* **偽陽率沒有量過。** 老譚要的混淆矩陣不存在。
  → **第一步不是實作閘,是實作分類器 + 只記錄不作用**,拿 CK 的真實提示歷史算偽陽率。
* 「高信心」的閾值沒有數字,而**在有偽陽率之前定閾值就是憑感覺** ——
  本週已經因為憑感覺定門檻付過三次代價(180 秒、4 輪、每工具額度)。

## 結論(可執行,且第一步不改變任何行為)

**Step 1(本次做):分類器 + 純記錄模式。**
在 `before_agent_start` 分類使用者提示,**不做任何事**,只把結果寫進 session
(`appendEntry`)。跑幾天,拿真實提示算偽陽/偽陰。

**Step 2(等資料):** 依實測偽陽率決定閾值,再啟用「先有計畫」。

**Step 3(再等資料):** 結束時回報 + 三選項。

**理由一句話:** 這是本週學到最貴的一課 ——
**在沒有噪音底線與偽陽率之前定門檻,三次都定錯了。**
這次先量再定。
