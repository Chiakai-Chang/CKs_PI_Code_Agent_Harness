## 第二輪:為什麼跑錯目錄 —— 把模型當理性行為者

**🎭 老聶:** 我要替模型講話。它不是笨,它是**照證據行動**。

Pi 的系統提示裡,`D:/MyProject/CKs_PI_Code_Agent_Harness` 以技能 `<location>` 出現 **28 次**,cwd 出現 **1 次**。然後它去那個路徑一看 —— **那裡真的有一個 `02_Task_Queue/`,裡面有二十個格式完整的任務包。**

它的 cwd 裡也有一個,只有一個任務。

**如果你是它,你會挑哪個?** 28 比 1 的證據,加上二十比一的內容。**它選的是證據更強的那個。這不是混淆,這是推論。**

**🎭 老陳:** 補一個技術事實。我們沒辦法改 Pi 的系統提示 —— 那 28 次是 Pi 自己產生的技能清單。

**🎭 小葉:** 那就要問另一個問題了:**為什麼 harness 的安裝目錄裡有一個真實的工作佇列?**

這是**這個 repo 自己的**任務佇列,gitignored,二十個任務包。它同時是:
1. 我們自己的工作狀態
2. **每個使用者的 agent 都看得到的、格式完整的誘餌**

**🎭 阿海:** 這在別人機器上會怎樣?他 clone 這個 harness,`02_Task_Queue/` 是 gitignored 所以**是空的** —— 誘餌不存在。**這個問題只在開發者機器上發生。**

**🎭 老魔:** 等一下。那我們五個 run 量到的「主要失效模式」,**可能是開發環境特有的假象**?

**🎭 Vera:** 這個反駁很強,而且可以查。分開看:

* **「跑到 harness 根目錄」** —— 四次都發生。這與佇列無關,是 28:1 造成的

## 這一輪最重要的一句

**🎭 老聶:** 模型不是混淆,是推論。28:1 的證據加二十比一的內容,它選了證據強的那邊。
**修法不是告訴它「你錯了」,是把它缺的那一半證據給它。**

**🎭 老莫:** 而我們自己犯的是同一個錯的鏡像 —— **我們的檢查也在用弱證據下強結論。**

**要求模型拿證據之前,先要求自己的檢查拿得出證據。**
