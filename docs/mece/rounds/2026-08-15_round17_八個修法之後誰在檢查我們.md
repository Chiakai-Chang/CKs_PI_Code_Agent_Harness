# SWOT

## Strengths
- 六條任務全部有**可重跑的證據**,其中 T-A16 是決定性實驗(120 / 102)
- 每一個新守衛都做過變異掃描,`reflect-budget` **0 存活者、無豁免**
- 三處未驗證都**主動標記**並寫下觸發條件,沒有一處假裝完成
- 換模型當天,自己寫的檢查抓到自己的判準錯誤 —— 工具開始回報作者

## Weaknesses
- **38 個測試檔掛在未釘住的 node**;CI 沒有 `setup-node`
- **這條分支零次 CI**,觸發條件只認 `main`
- 命名空間修法**做了三處、漏了三處**,而註解讀起來像做完了
- allowlist 40 條,鍵用行號,**repo 自己記過兩次會過期**
- 三個「等真實 session 來驗」的 IOU,而重查靠人記得

## Opportunities
- 釘 node 是**一個 step**,立刻讓 38 個檔在 runner 上真的跑
- 「跳過太多就失敗」是一條**便宜且會紅**的檢查,直接補上 `skipUnless` 的盲點
- constructor 參數屬性的知識已經寫在 `goal-restate.ts:130`,**只差一個 grep**
- 開 PR 就能讓整批東西第一次進 CI,不需要改任何程式

## Threats
- 釘 node 到 22 之後,若 runner 上某些測試在 Linux 上本來就會紅,**會一次紅一大片** ——
  那是好事,但要有心理準備,而且要在合併前面對
- 補完命名空間可能讓某些既有 fixture 的解析結果改變(前綴可選,理論上不會,要測)
- 再加檢查會讓本地跑一次的時間更長,而慢的檢查最後沒有人跑

# TOWS

| | Opportunities | Threats |
|---|---|---|
| **Strengths** | **SO(今天做)**:釘 node + 跳過門檻檢查 + 補完命名空間 + constructor grep。四件都便宜、都會紅、都不改行為 | **ST(紀律)**:合併前必須讓 CI 至少跑一次綠;紅了就修,不夾帶 |

## 這一輪最重要的四句

1. **38 個測試檔掛在一個沒有釘住的 node 上,而 CI 沒有裝它。**
   `skipUnless` 不會失敗,它會消失,而 `Ran N tests, OK` 裡的 N 沒有人在看。
2. **這條分支八個 commit,零次 CI。** 我們在 commit 訊息裡寫「CI is a feature」,
   而這批東西沒有進過那個 feature。
3. **這個 repo 的失敗模式不是不知道,是知道了沒有執行點。**
   換模型清單、constructor 參數屬性、allowlist 鍵會過期 —— 三次同一個形狀,
   全都是**寫下來的判斷沒有變成會執行的東西**。
4. **修一半比不修更危險**,因為註解現在寫著「已修」。命名空間補了三處、漏了三處。
