## SWOT

### Strengths
- CASE 狀態機的每一步都是 `tool_call`,發生前可見、可擋
- 六條規則純結構可判定,零模型配合
- 作用域(`02_Task_Queue/` 內的寫入)與既有守衛正交,無順序衝突
- `tool_call` block 是本輪唯一實測有效的通道
- 擋阻理由進 tool result → 可被 `GUARD_MARKERS` 統計

### Weaknesses
- 全部只在 CASE 專案已存在時有效
- `measure-triggers.py` 測不到(`--print` + 乾淨暫存目錄)
- 協定是散文,程式與散文會漂移
- `case-bridge` 目前只做注入,加守衛會混合兩種職責

### Opportunities
- `verify.py --strict` / `--queue` 剛做好,可在 `REVIEW→DONE` 當閘
- harness 自寫 `action_log.jsonl` 不需任何配合
- `/browse` 是同一問題的既有解法先例
- CK 的真實專案是天然測試場

### Threats
- 造六道鎖給一扇沒人走的門
- 強制得越細,敷衍形狀越明確(引用閘:編造 0→4)
- 抄上游轉換表 = 分叉(`reference/oh-my-pi` 的疤)
- 又一組「測試全綠、實測 0 次開火」的未驗證守衛

## TOWS

| | **Opportunities** | **Threats** |
|---|---|---|
| **Strengths** | **SO-1** 六條守衛獨立成模組掛 `case-bridge`,作用域天生正確<br>**SO-2** `REVIEW→DONE` 直接跑 `verify.py --strict` 當閘,新旗標立刻有用武之地 | **ST-1** 只擋明確非法,不強制細節 → 減少敷衍面<br>**ST-2** 理由字串固定並進 `GUARD_MARKERS` → 事後查得到 |
| **Weaknesses** | **WO-1** 先做守衛(單元測試可驗),再做 `/case`(只能靠真實使用驗)<br>**WO-2** 抄不變式而非轉換表,用測試綁住並標明上游是唯一真相 | **WT-1** 守衛只在 `02_Task_Queue/` 內作用 → 不用 CASE 的人零感知<br>**WT-2** 明說這批守衛在探針中不可驗,靠 CK 的真實 session |

## 收斂決策

### 順序(每步之間量一次)

| # | 項目 | 為何是這個位置 |
|---|---|---|
| **C1** | 六條 CASE 執行守衛(獨立模組,掛 `case-bridge`) | 能被單元測試驗證的那一半先做;`/case` 一開就有規矩 |
| **C2** | harness 自寫 `action_log.jsonl` | 不依賴守衛,但需要任務目錄 |
| **C3** | `/case` 確定性入口(`/browse` 模式) | 只能靠真實使用驗證,排最後 |

### C1 的六條

| # | 規則 | 判定 | 嚴格度 |
|---|---|---|---|
| 1 | 非法狀態轉換 | 寫入前讀舊值比對 | 只擋明確非法(如 `PENDING→DONE`),未知組合 fail open |
| 2 | 同時兩個 `IN_PROGRESS` | 掃 queue 目錄 | 硬擋 |
| 3 | Worker 自我核可 | 同 session 先 `IN_PROGRESS` 後 `DONE` | 硬擋 |
| 4 | `DONE` 前無 `retro.md` | 檔案存在性 | 硬擋(§13a 本來就是 error) |
| 5 | 寫出任務目錄之外 | 路徑比對 | 硬擋 |
| 6 | `REVIEW→DONE` 未過 `verify.py --strict` | 跑驗證器 | 硬擋,驗證器不可用時 fail open |

全部沿用既有退場機制:同一條擋滿 3 次本 session 退場。

### 明確不做

| 方案 | 理由 |
|---|---|
| 把 CASE 轉換表整份抄進 harness | 分叉。只抄不變式 |
| 強制「必須經過每一個中間狀態」 | 強制越細,敷衍形狀越明確 |
| 自動 bootstrap | 汙染不知情使用者;而且啟動是決策,不是轉換 |
| 先做 `/case` | 先開門後立規矩,中間有空窗;且入口無法被單元測試驗證 |

## 妥協(明列)

1. **C1 在探針中不可驗證。** 與深度閘、產出閘同一個限制,誠實標記,靠 CK 的真實 session。
2. **六條全部只在 CASE 專案內有效。** 不解決「模型不會自己開始用 CASE」—— 那是 C3 的事。
3. **抄不變式仍是抄。** 上游改了不變式(極不可能)會漂移,用測試與註解標明唯一真相在上游。
