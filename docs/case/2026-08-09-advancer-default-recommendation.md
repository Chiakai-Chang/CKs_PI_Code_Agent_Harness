# `enableCaseAdvancer` 預設值:建議與根據(2026-08-09)

**狀態:建議,未執行。** 擁有者要自己先試,重測暫緩。

## 建議

**先跑基準線重測 ≥3 次,再改預設值。** 順序有理由,不是保守。

## 為什麼是這個順序

旗標一開,推進器會**主動觸發回合** —— 那是本 harness 裡最大的行為改變,
比任何擋阻都大。而 GateGuard 的疤正是「沒人跑過的東西直接上線」:
一個沒人執行過的機制上線後,拒絕了每個 session 的第一個 bash 指令。

目前的證據**只涵蓋研究型情境**:

| 情境 | 樣本 | 結果 |
|---|---|---|
| 研究型 | 4 次(出貨設定 2 次) | 4/4 走到 `REVIEW` |
| 基準線 | 3 次,**但用的是舊版程式碼** | 3/3 走到 `REVIEW` |

基準線那三次跑在:4 輪額度、無階段轉換通知、無狀態合法性檢查。
**那不是現在會出貨的東西。** 預設值要對所有情境負責,而不是對我量過的那個。

## 你要自己試的話,這樣開(不必改全域設定)

在**那個專案的根目錄**放一個 `.pi-harness.json`:

```json
{ "enableCaseAdvancer": true }
```

* **只對那個專案生效**,其他專案完全不受影響。
* 不必動 `pi-config/harness-config.json`,不必 `restore`。
* 想關掉就刪掉那個檔案。

想讓「先認領再開工」更嚴格,可以加(範圍 8–12,只能調嚴不能調鬆):

```json
{ "enableCaseAdvancer": true, "caseClaimRefusalTurns": 12 }
```

## 你會看到什麼(依實測)

1. 開頭若直接搜尋,會被擋,理由會**指名下一步**(把 status.txt 改成 IN_PROGRESS)。
   最多擋 8 輪,之後放行 —— 那是刻意的,免得鎖死。
2. 認領之後會收到一則「研究工具已放開,請盡量搜」的訊息。
3. 之後模型會寫 `planning.md`、`output.md`、`retro.md`,把狀態推到 `REVIEW`。
4. 到 `REVIEW` 時它應該**把 DoD 逐條講給你聽並給三個選項**,而不是叫你自己看檔案。
   你回一句「通過」它就會結案(C.A.S.E. §7 Path A)。

## 已知限制(先講,免得你踩到才發現)

* **只在有 `02_Task_Queue/` 的 C.A.S.E. 專案生效。** 一般專案完全不受影響。
* 一次研究型 run 在本機模型上要 **20–40 分鐘**。
* 認領樣本仍然小(n=2 於出貨設定),而模型行為是機率性的 —— 會有 run 不如預期。
* 若你看到模型在跑而終端沒動靜,`python scripts/measure-advancer.py --status`
  可以分辨「正在跑」與「洩漏的孤兒」。
