# Task_013_write_forms_blind_spot — 看不見的寫入形式

**狀態:REVIEW**

## 為什麼這一項排在存活變異之前

`sed -i` 對 `writeTargets` 完全不可見,而讀那個函式的是**全專案僅有的三個被實測證明
改變過模型行為的守衛**:目錄圍堵(一天 11 與 72 次擋阻,一次都沒漏)、
C.A.S.E. tool-first(21 次 status 寫入全走 `write`/`edit`)、引用閘(檔案內網址 0 → 10)。

**一種沒被剖析的拼法,就是這三個守衛共用的後門。** 變異掃描的存活者是品質債,這個是活的繞道。

## 動工前的事實修正

roadmap 寫「`sed -i`、`tee -a`、`dd of=` 完全不可見」。**`tee` 早就在 `DEST_ALL` 裡。**
八個指令的探針實測為憑。實際缺口是 `sed -i` 與 `dd of=`,一併納入 `perl -i`
(同一條程式路徑、同一組測試 —— 只補其一是把同類缺口留一半而外觀看起來補好了)。

## 兩個設計決定

**一、沒有 `-i` 就不算寫入。** `sed 's/a/b/' f` 印到 stdout。擋掉它會讓使用者關掉整個 bridge,
而這個檔案的檔頭本來就寫著「會擋掉正常工作的守衛,一天之內就會被關掉,然後什麼都保護不到」。

**二、`-e` 的下一個 token 是腳本,不是檔案。** 把 `s|a|b|` 當成路徑,
會讓目錄圍堵因為**守衛自己的剖析錯誤**而擋住合法編輯 —— 最惡劣的誤判形式。

同一個 `|` 也逼出了分段方式的修正:分段位置改由**遮罩過**的文字決定、文字仍取自原文。
這是這個檔案處理重導向時已經記載過的手法,不是新發明。

## 變異掃描當場否決了作者的判斷

DoD 有一條「新分支要有測試守住」。第一次跑,**三個存活者全在剛寫好的 `inPlaceTargets` 裡**:
迴圈起點 `0->1`、`&&->||`、以及它設的 `scriptSeen`。

三個只有在「長旗標排最前面且自帶腳本」時才觀察得到(`sed --expression='...' -i f`),
而我挑的測試案例剛好都不是那個形狀。補一條測試殺掉兩個。

**第三個的處理不同:`t.includes("=") &&` 是冗餘的**,後面的正規表達式本來就蘊含 `=`。
**測不到的條件要刪掉,不是為它寫測試。** 變異存活有時候是在說「這裡有多餘的東西」。

重跑:新分支 7/7 全殺。

## 平權測試的局限,寫下來

新的七個指令在改動前**兩份抽取器都回 `[]`**,所以平權測試從頭到尾是綠的、對這個缺口完全沉默。
加進清單之後仍然綠,因為兩邊我都改了。
**平權只證明兩份一樣,不證明兩份是對的** —— 所以另外加了一條釘住答案的測試。
