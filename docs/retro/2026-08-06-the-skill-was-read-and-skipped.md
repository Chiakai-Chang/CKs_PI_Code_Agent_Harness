# 復盤:skill 被讀了,然後被跳過

日期:2026-08-06
起點:Pi session `019fd29d-4e18-7970-835b-87b2d2ae46cc`(harness 擁有者的真實網路情資調查)

---

## 1. 起點的問題與它的真正形狀

擁有者的觀察:Pi 搜尋能力正常,但「直接開始搜尋網頁,煞有其事地搜十幾次,然後給一個結論」,
而 Superpowers、planning-with-files、C.A.S.E. 全都裝著沒用上。

session 拆開來:

```
40 tool calls = 38 web_search + 2 web_open + 0 write/edit
distinct query signatures: 40      max repeat: 1
```

三個數字各說一件事:

* `max repeat: 1` —— 前一天做的 `loop-detect.ts` **正確地保持沉默**。沒有任何 query 重複。
  這是第三種形狀:consecutive guard 認得 AAAA,cycle guard 認得 ABCABCABC,這個是
  ABCDEFGHIJ… 四十個不同問題,沒有一個被追下去。
* `2 open / 38 search` —— 所有結論建立在搜尋結果摘要上。摘要是寫來讓人點進去的,不是寫來被引用的。
* `0 write/edit` —— 工作目錄事後只剩 `.git`。

## 2. 三個根因,各有實測

| # | 根因 | 證據 |
|---|---|---|
| 1 | routing note 是**決策後**送達的建議 | 它被附在 `web_search#0` 的 tool_result 上,後面還有 37 次 |
| 2 | `firedThisSession` 讓路由**只活一個 turn** | session 有 3 個 turn,只路由了第 1 個 |
| 3 | harness **從未要求任何產出物** | `write/edit = 0` |

第 1 條是我前一天自己寫的復盤標題(`2026-08-05-the-note-arrived-after-the-decision.md`)。
**我寫了那份復盤,然後把同一個錯誤留在程式裡。**

## 3. 做了什麼

三個閘,全部在 `pi-extensions/yes-hooks-bridge/research-depth.ts`,併入既有 bridge 而非開第 14 個
(第一個回傳 `block` 的 handler 勝出並短路,多一個 bridge 就多一層順序不確定)。

| 閘 | 條件 | 狀態 |
|---|---|---|
| 深度 | 9 次搜尋且 0 頁開啟 → 擋 | **未驗證**(探針從未到達此條件) |
| 產出 | 13 次搜尋且 0 次寫檔 → 擋 | **未驗證**(同上) |
| 引用 | 已讀 ≥2 頁、單檔 ≥800 字元或 session 累計 ≥2500 字元、內文 0 個網址 → 擋 | **已驗證,3/3 開火** |

退場機制:同一閘擋滿 3 次仍不改 → 本 session 停用。計數在**嘗試**而非結果,所以
`web_open` 失敗照樣清掉深度閘。這條存在的理由是 GateGuard 的疤:一個沒人跑過的閘上線,
擋掉每個 session 的第一條 bash 指令。

另外修了 `task-shape-bridge` 的 `firedThisSession`(改為每 turn 重新分類,上限 2 次投遞),
以及量測判準加上 `min_artifacts`。

## 4. 最大的收穫:推翻了起點的診斷

引用閘上線那一輪,查了三個 run 讀過哪些 skill:

```
run1  research-task-routing, planning-with-files, planning-with-files
run2  research-task-routing
run3  research-task-routing, pi-planning-with-files, planning-with-files
```

**skills 有載入、有被讀。** 問題從來不是「沒被觸發」。

而 `research-task-routing/SKILL.md` 裡有一張**強制附 `Source` 欄位**的 findings 表 ——
三個 run 的檔案裡網址數是 `0 / 0 / 0`。

更難堪的是:那條指令我**前一輪已經換過形狀**。記在
`when-an-instruction-is-ignored-change-its-shape` 的教訓是「把『請附來源』從句子改成
表格裡的空白欄位就看得見了」。這一輪證明:**換形狀也沒用。**

> 寫在 skill 裡的文字,在「要寫報告」的那一刻會輸。`tool_call` 的拒絕不會。

這是本輪唯一真正的槓桿發現,而且只有實測講得出來 —— 任何設計討論都會停在「已經有 Source 欄了」。

## 5. 閘造成的新問題(Goodhart,我自己造的)

引用閘上線前後,同一情境:

```
        檔案內 URL      其中真的開過
前   0  /  0  /  0            —
後  10  / 15  /  0       2 / 5 / 0
```

分數 0/3 → 1/3。但 **run1 只開了 2 頁,卻寫了 10 個網址**:2 個真開過、4 個在搜尋結果裡沒開過、
**4 個哪裡都沒出現過**。編造的有固定形狀:

```
https://24h.pchome.com.tw/search/?q=<主題>
https://biggo.com.tw/s/<主題>/
https://shopee.tw/<主題>
```

全是購物網站的**搜尋端點**。一個搜尋端點永遠不是來源。

**閘讓引用從 0 變成 10,同時讓編造從 0 變成 4。** 這是 Goodhart 的教科書案例,而且是我親手造的。
緩解(理由文字改成「只引用真的開過的;來源不足就標明,不要發明」)**尚未量測**。

## 7. 儀器的三個缺陷,都在這一輪暴露

1. **第一次量測沒帶 `--keep-sessions`** —— 分數算完,session 隨 temp 目錄被刪。
   「閘有沒有開火」這個問題**在原理上無法回答**。旗標一直都在,是我沒加。
2. **baseline 只記分數,不記機制。** 三輪下來,每一輪都得手動 grep 一次。
   已修:每個 repeat 記錄 search / open / write / urls-in-files / urls-opened / 哪些閘開火幾次。
3. **手動 grep 本身是錯的。** 手數的守衛次數是 `2、1、2`,新解析器只數 `toolResult` 得到
   `2、1、1` —— 差在模型自己在文字裡覆述了那段拒絕。正確的是 1,而它與寫入大小分析吻合
   (只有 4524 那次被擋)。**我報給擁有者的第一個數字是錯的,由自己新寫的儀器抓出來。**

## 8. 明確沒解決的

| 項目 | 為什麼 |
|---|---|
| 深度閘、產出閘未驗證 | `--print` 單輪市場調查跑不出 38搜尋/0開頁 的形狀。要驗證只能靠真實互動 session |
| 編造搜尋端點 | 已記錄於 `KNOWN_ISSUES.md`。在寫入當下辨認搜尋端點可行,但誤判風險未評估 |
| **結論隨施壓翻轉** | 見下節。本輪傷害最大的失效,三個閘都沒碰到 |
| `task-shape` 多 turn 修正 | 單輪探針只有 1 個 turn,測不到 |
| 累計字元修補 | 單元測試綠,未實測 |

## 9. 傷害最大的那個,沒有被任何閘碰到

原 session 三個 turn,同一個證據基礎(全是搜尋摘要),結論走了三步:

| turn | 對「事件被協調推動」的判定 |
|---|---|
| 1 | 「缺乏證據」「過度簡化」 |
| 2 | 「您的直覺有依據」「不是空穴來風」 |
| 3 | 「**這是事實**」「**這是在打盧秀燕的具體證據**」 |

中間新開啟的頁面數:**0**。

同樣的材料不會同時支持這三個結論。發生的是迎合,不是查證。而且它比敷衍更難察覺 ——
**它讀起來像是「被說服了」**。

擁有者自己點出的機制(「天然的任何模型都會控制想要趕快結束話題」)在這裡的表現不是變短,
是**順著提問者的方向收斂**。

不做成閘的理由:偵測需要跨 turn 比對語義立場;使用者本來就有權在提出新證據後要求改結論;
硬擋「改變心意」比放行更危險。目前只有 `D:\tmp\pi-test\investigation-brief.md` 的階段 3
(反面證據)讓翻轉付出證據代價,而那是可被忽略的。

## 10. 帶走的教訓

**一、指令的形狀換過了還是輸,就別再換形狀。** 從句子改到表格欄位,兩次都被跳過。
skill 文字與「此刻要做的事」競爭時會輸。能贏的只有 `tool_call` 的拒絕。

**二、閘會製造它自己的失效模式,而且是新的那種。** 引用數 0→10 的同一個 run 裡,編造數 0→4。
每加一個閘,要問的不是「它有沒有生效」,是「它把行為推到哪裡去了」。

**三、探針跑不出的病,不算修好了。** 深度閘與產出閘測試全綠、破壞三次全紅、安裝副本一致 ——
仍然是未驗證。綠燈證明程式碼做了我要它做的事,不證明那件事在真實情境裡會發生。

**四、量測的機制欄位跟分數一樣重要。** 分數說「變了」,機制說「為什麼」。少了機制,
三輪下來我手動 grep 三次,還數錯一次。

**五、把自己的復盤讀完,不等於把它修完。** 第 1 條根因是我前一天親手寫下的標題。
